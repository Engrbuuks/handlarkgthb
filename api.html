API guide

Connect Handlark to your own tools: read and add work with the REST API, get signed webhooks as things happen, post news to Slack, Microsoft Teams and Discord, or use Zapier and Make without writing code.

Base address https://YOUR_PROJECT_REF.supabase.co/functions/v1/api/v1

In short: make a token under Settings, Integrations (or in your account), send it as Authorization: Bearer hl_..., and every request runs with exactly your permissions, cut down to the scopes you ticked. Lists come in pages of up to 200. Webhooks are signed with HMAC SHA256 and retried for about two days.

Start in two minutes

  1. In Handlark, open Settings, Integrations, API tokens (members: your account, API tokens) and choose Make token. Copy it: it is shown only once.
  2. Call the API with it. This lists your newest open tasks:
curl "https://YOUR_PROJECT_REF.supabase.co/functions/v1/api/v1/tasks?status=new&limit=5" \
  -H "Authorization: Bearer hl_ws_your_token_here"

Every answer is JSON. A list looks like this:

{
  "data": [
    { "id": "t1", "title": "Reconcile September bank statements", "status": "in_progress", "priority": "high",
      "client": { "id": "c9", "name": "Brooks Dental (US)" }, "assignee": { "id": "p-kemi", "name": "Kemi Bello" },
      "due": "2026-10-16", "created_at": "2026-10-14T10:00:00.000Z", "updated_at": "2026-10-15T09:12:44.000Z" }
  ],
  "next_cursor": "eyJrIjoxNzYwNDM2MDAwMDAwLCJpZCI6InQxIn0",
  "has_more": true
}

API tokens and scopes

There are two kinds of token. Both are shown once, stored only as a SHA 256 hash, can be revoked at any time, show when they were last used, and every change they make is written to the history with the token's name.

Workspace token hl_ws_The ownerThe owner, cut down to its scopes. Best for Zapier, Make and company systems. It stops working if the workspace gets a new owner.
Personal token hl_pt_Anyone in the workspaceThe person who made it, never with more than they may do in the app. If their role changes, the token follows at once.

Tokens are not affected by two step sign in: treat them like passwords, keep them out of code you share, and revoke any you no longer use.

What never leaves

The API, webhooks and chat alerts follow the same rules as the app, with a little more held back:

  • Private tasks and anything in a private list never leave, not even through the owner's token.
  • People the owner hid are never listed, and their work is left out. Where a name would show, it says "A teammate".
  • People are names, job titles, roles and teams. Never emails, phone numbers, locations, pay rates or payout details.
  • Time entries never carry pay or bill rates, and Proof mode screenshots never leave through the API at all.
  • Leave says who and when, never the kind of leave or the note.

Requests, pages and errors

Pages

Lists are newest first. Send limit (1 to 200, 50 by default) and, for the next page, the next_cursor you got as cursor. When has_more is false you have everything.

GET /tasks?limit=100
GET /tasks?limit=100&cursor=eyJrIjoxNzYwNDM2MDAwMDAwLCJpZCI6InQxIn0

Dates and times

Days are YYYY-MM-DD. Moments are ISO 8601 in UTC, such as 2026-10-14T10:00:00.000Z. Filters from and to are days in the workspace's deadline time zone; updated_since takes an ISO time, a day or milliseconds.

Errors

Every error has the same shape and a matching HTTP status:

{ "error": { "code": "forbidden", "message": "This token does not have the invoices:read scope" } }
StatuscodeMeaning
401unauthorizedNo token, an unknown one, or one that was revoked
403forbiddenThe token lacks the scope, or its person may not do this
403read_onlyThe workspace's plan ended, so it is read only
404not_foundNothing with that id that this token may see
409proof_modeThis client uses Proof mode, so its timer must be started in the app, where the screen is shared
410goneA connect code that has expired
405methodThat method is not allowed on that address
422invalidThe request broke a rule; the message says which
429rate_limitedToo many requests; wait for Retry-After seconds
503serverSomething broke on our side; try again shortly

Limits

  • 120 requests a minute for each token, and 600 a minute for all the tokens of one workspace together.
  • Writes count toward the same daily limits as in the app (for example 200 new tasks an hour).
  • Answers carry X-RateLimit-Limit and X-RateLimit-Window; a 429 carries Retry-After.

Endpoints

All addresses below follow the base address at the top of this page.

GET/me

The workspace, the token (its kind and scopes as they apply right now) and the person it acts as.

GET/tasks

Filters: status (new, in_progress, waiting, review, done), client_id, assignee_id, updated_since, request=true (only client requests), open=true (everything not done), link (tasks that carry this web address as a link; assignee_id=me also works). Scope tasks:read.

GET/tasks/{id}
POST/tasks

Fields: title (required), details, client_id, assignee_id, due, priority (high, normal, low), status, type, start_time, end_time, budget_minutes, and link with link_name to attach a web page (https only) as a link on the task. Scope tasks:write. Answers 201 with the task.

curl -X POST "$BASE/tasks" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"Send the October invoice","client_id":"c9","assignee_id":"p-kemi","due":"2026-10-31","priority":"high"}'
PATCH/tasks/{id}

Change any of the fields above. To finish a task send {"status":"done","proof":"Sent to the client"}: the proof line is posted on the task, as in the app. If the task needs sign off, it goes for review.

GET/clients

Clients and internal clients, without rates. include_archived=true adds archived ones. Scope clients:read.

GET/people

Names, job titles, roles (owner, manager, team_lead, member) and teams. Scope people:read.

GET/time_entries

Filters: from, to, person_id, client_id, status (draft, submitted, approved, rejected), billable, updated_since. Scope time:read. A member's token sees their own time; a manager's or team lead's, the time of the people they look after.

POST/time_entries

Send start and end (ISO), start and minutes, or date and minutes; plus task_id or client_id, note, billable, and person_id to log for someone you manage. Scope time:write. The same checks as the app apply (at most 16 hours added by hand a day, no time in the future).

curl -X POST "$BASE/time_entries" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"task_id":"t1","start":"2026-10-15T09:00:00Z","minutes":90,"note":"Matched the Chase statement"}'
GET/timer

The token's own person right now: running (the timer, its task, client, start and minutes, or null), clock (clocked in, on a break, client, since), check (an open still working check, or null), today_minutes and proof_client_ids (clients whose timers must start in the app). Scope time:read.

POST/timer/start POST/timer/stop

Start a timer on task_id (stopping any other one), or stop the running timer with an optional note. Timers started through the API never count as screen shared, so a Proof mode client answers 409 proof_mode. Both answer with the same shape as GET /timer. Scope time:write.

POST/timer/answer POST/timer/active

Answer the still working check with answer (yes, pause or stopped, with stopped_at for stopped) and check_id; or tell Handlark the person is active, the same as using the app. Scope time:write.

POST/connect

Used by the browser extension, with no token: send code (the 10 characters shown in the app under your account, Browser extension) and browser. Answers 201 with a personal token (scopes tasks:read, tasks:write, time:read, time:write, clients:read), the workspace and the person. A code works once, for 10 minutes; at most 20 tries in 10 minutes from one address.

DELETE/me

The token revokes itself, for example when you disconnect the extension. Answers 200 with {"data":{"id":"…","revoked":true}}.

GET/timesheets

Weekly timesheets with their status. Filters: from, to (the week's Monday), person_id, status. Scope time:read.

GET/invoices and /invoices/{id}

Filters: status (draft, sent, paid, void), client_id, from, to (issue date). Scope invoices:read.

GET/meetings

Meetings you can see, with their video link when you open one by id. Filters: from, to, status. Scope meetings:read.

GET/events

The webhook events this token may follow. GET /events/{type}/sample gives up to three recent examples, shaped exactly as webhooks send them.

GET/hooks POST/hooks DELETE/hooks/{id}

Webhooks added through the API, for tools such as Zapier and Make. POST takes url and events, and answers with the signing secret once. Scope webhooks.

Webhooks

The owner (or a manager granted workspace settings) adds webhooks under Settings, Integrations, Webhooks: an https address and the events it wants. Each event is sent as a POST with a JSON body:

POST /your/endpoint
Content-Type: application/json
User-Agent: Handlark-Webhooks/1.0
Handlark-Event: task.done
Handlark-Delivery: 1043
Idempotency-Key: evt_9f2c41a7b03e5d18c6a2f704
Handlark-Signature: t=1760610000,v1=5b1f0e...c94d

{ "id": "evt_9f2c41a7b03e5d18c6a2f704", "type": "task.done", "created_at": "2026-10-16T10:20:00.000Z",
  "workspace": { "id": "7f3c2a10-...", "name": "Brightline Assistants" },
  "data": { "id": "t1", "title": "Reconcile September bank statements", "status": "done", "...": "..." } }
  • Answer quickly with any 2xx status. Anything else, no answer in 10 seconds, or a redirect counts as a failure.
  • Retries wait 1, 5, 15 and 60 minutes, then 3, 6, 12 and 24 hours: nine tries over about two days. The delivery log in the app shows each one, and you can send any of them again.
  • Exactly once on your side: the same event can arrive twice if a reply was lost. Keep the Idempotency-Key (the event id) and ignore one you have seen.
  • Switched off after 20 failures in a row, and the owner gets an email. Switch it back on once the endpoint works.
  • Only public https addresses. Addresses that point to private networks, this machine, link local ranges or cloud metadata services are refused when saved and checked again before every delivery.
  • The Send test button sends a ping event.

Checking a signature

The signing secret (whsec_...) is shown once when you add the webhook; New signing secret replaces it. Work out HMAC SHA256 of t + "." + body with the secret, compare it with v1 in constant time, and refuse a t more than 5 minutes away from now. Use the raw body exactly as it arrived.

Node.js

import crypto from 'node:crypto';
function genuine(secret, header, rawBody) {
  const m = /^t=(\d+),v1=([0-9a-f]{64})$/.exec(header || '');
  if (!m || Math.abs(Date.now() / 1000 - Number(m[1])) > 300) return false;
  const want = crypto.createHmac('sha256', secret).update(m[1] + '.' + rawBody).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(want), Buffer.from(m[2]));
}

Python

import hmac, hashlib, re, time
def genuine(secret, header, raw_body):
    m = re.fullmatch(r't=(\d+),v1=([0-9a-f]{64})', header or '')
    if not m or abs(time.time() - int(m[1])) > 300:
        return False
    want = hmac.new(secret.encode(), (m[1] + '.').encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(want, m[2])

PHP

function genuine($secret, $header, $rawBody) {
  if (!preg_match('/^t=(\d+),v1=([0-9a-f]{64})$/', $header ?? '', $m) || abs(time() - (int)$m[1]) > 300) return false;
  return hash_equals(hash_hmac('sha256', $m[1] . '.' . $rawBody, $secret), $m[2]);
}

Slack, Microsoft Teams and Discord

Under Settings, Integrations, Chat alerts, paste an incoming webhook address and choose events. Messages are formatted for each service, can be kept to one client or one team, and can wait through quiet hours (for example 18:00 to 08:00) so nobody is pinged at night.

  • Slack: Apps, Incoming Webhooks, Add to Slack, pick the channel, copy the Webhook URL (it starts with https://hooks.slack.com/services/).
  • Microsoft Teams: in the channel, More options, Workflows, "Post to a channel when a webhook request is received", then copy the address it gives you.
  • Discord: channel settings, Integrations, Webhooks, New Webhook, Copy Webhook URL.

Chat addresses are stored encrypted and shown only as their last 4 characters. Attendance alerts name a person: send them only to a private channel for team leads.

Zapier and Make

Both connect with a workspace token. Triggers (new task, task done, time entry, timesheet approved, invoice paid, client request, meeting, leave) arrive at once through webhooks that Zapier and Make add and remove for you. Actions create a task, update a task and log time.

The app definitions are in the integrations folder of your Handlark files, with steps to publish them from free Zapier and Make developer accounts. Until they are listed publicly, use the private invite link they give you, or Zapier's Webhooks and Make's HTTP modules with this API.

Versions

This is version 1 (/api/v1). Fields may be added to answers and events at any time, so ignore ones you do not know. Anything that would break existing code gets a new version, and version 1 keeps working for at least 12 months after that.

  • 1.15.0, 16 October 2026: the timer endpoints, /connect for the browser extension, DELETE /me, the open and link filters on tasks, and links on new tasks.
  • 1.12.0, 16 October 2026: version 1 of the API, API tokens, signed webhooks, chat alerts, Zapier and Make.
